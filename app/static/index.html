05

How it works

The hash is the address — the same idea Walrus is built on.

01 · SEAL

Hash the exact bytes. SHA-256 of your file is computed; that 64-character hash becomes the document's blob id, and the bytes are stored under that id. Same bytes → same id, always.

02 · VERIFY

Re-hash and compare. Upload a suspect copy: if its hash equals the sealed blob id, it is byte-for-byte the original (AUTHENTIC). One flipped character → a totally different hash → TAMPERED. An unknown hash → NOT FOUND. This comparison needs no server lookup, so it works even when the seal happened on a different server instance.

03 · AUDIT

Chain every receipt. Each seal and verify appends a receipt whose hash covers the previous receipt. Alter any entry and the chain check fails at that exact receipt.
